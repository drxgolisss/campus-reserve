# Урок 1. Основа Django-проекта

## Результат этапа

После этого этапа у нас есть минимальное веб-приложение, которое:

- принимает HTTP-запрос на адрес `/`;
- вызывает Django view;
- формирует HTML из template;
- подключает CSS;
- запускается локально или через Docker Compose;
- может использовать PostgreSQL;
- проверяется автоматическим тестом.

Пока здесь намеренно нет авторизации, каталогов и бронирований. Они будут добавляться отдельными понятными частями.

## Путь одного запроса

Когда браузер открывает `http://localhost:8000/`, происходит следующее:

1. `campusreserve/urls.py` получает путь `/`.
2. Корневой URL-конфиг передаёт его в `core/urls.py`.
3. `core/urls.py` выбирает функцию `home`.
4. `core/views.py` вызывает `render()`.
5. Django загружает `templates/core/home.html`.
6. Этот шаблон расширяет общий `templates/base.html`.
7. Готовый HTML возвращается браузеру как HTTP response.

```text
Browser
   -> campusreserve/urls.py
   -> core/urls.py
   -> core/views.py
   -> templates/core/home.html
   -> HTML response
```

## Что означают основные понятия

### Project

`campusreserve` — Django project. Он хранит общую конфигурацию всего сайта: настройки, главные URL, WSGI и ASGI entry points.

### App

`core` — Django app. App отвечает за одну область функциональности. Позже появятся отдельные приложения для ресурсов и бронирований.

Один project может содержать несколько apps.

### URL

URL pattern связывает адрес страницы с Python-функцией. Например, пустой путь `""` означает корневую страницу `/`.

### View

View принимает объект request и возвращает response. Наша функция `home` пока только отображает HTML-шаблон.

### Template

Template — HTML с конструкциями Django. `{% extends "base.html" %}` позволяет всем страницам использовать общий каркас, навигацию и подключение CSS.

### Migration

Migration — версия структуры базы данных. Команда `migrate` создаёт таблицы, необходимые встроенным Django-приложениям: пользователям, сессиям и административной панели.

## Почему две настройки базы

В Docker переменная `POSTGRES_HOST` установлена, поэтому Django использует PostgreSQL. При локальном учебном запуске без этой переменной используется SQLite. Это позволяет быстро выполнять проверки, даже когда Docker Desktop закрыт. Итоговый контейнерный запуск и демонстрация будут работать с PostgreSQL.

## Команды этапа

Запуск через Docker:

```bash
docker compose up --build
```

Локальный запуск:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Проверки:

```bash
python manage.py check
python manage.py test
```
